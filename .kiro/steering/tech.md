# Technical Steering

## General Principles

Write clean, readable and maintainable code.

Prefer simplicity over cleverness.

Avoid premature optimization.

Use strong typing whenever possible.

---

## Language

Primary language:

TypeScript

---

## Frontend

Framework:

Next.js

UI:

React

Styling:

Tailwind CSS

State Management:

Prefer local state.

Use shared state only when necessary.

---

## Backend

Backend services are provided by Supabase.

Business logic should be organized by domain.

Database access should remain encapsulated.

---

## Database

PostgreSQL.

Use UUIDs.

Use soft deletes when appropriate.

Never expose database implementation directly to UI.

---

## Offline

Nova POS is Offline First.

Every feature must consider:

- Local persistence
- Synchronization
- Conflict resolution
- Recovery

Offline support is not optional.

---

## Authentication

Nova POS

- Local authentication
- Username/password
- Offline login

Nova GanaMás

- Supabase Auth
- Email OTP

Authentication is product-specific.

---

## API Design

Use REST APIs.

Keep endpoints resource-oriented.

Avoid unnecessary nesting.

Return predictable responses.

---

## Error Handling

Errors must be explicit.

Never swallow exceptions.

Return meaningful messages.

Log unexpected failures.

---

## Security

Validate every input.

Use least privilege.

Encrypt credentials.

Never trust client data.

---

## Testing

Every feature should include:

- Unit tests
- Integration tests when required

Critical business logic should always be tested.

---

## Code Quality

Small functions.

Small files.

Single responsibility.

Readable naming.

Avoid duplicated logic.

---

## Performance

Optimize only when necessary.

Measure before optimizing.

Prefer maintainability over micro-optimizations.

---

## Documentation

Every specification generated by Kiro should remain aligned with:

- Product vision
- Architecture
- MVP scope
- Offline First
- Multi-Tenant
