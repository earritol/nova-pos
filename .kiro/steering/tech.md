# Technical Steering

## General Principles

Write clean, readable, and maintainable code.

Prefer simplicity over cleverness.

Avoid premature optimization.

Use strong typing whenever possible.

Favor explicitness over magic.

---

## Language

Primary language:

TypeScript

Enable strict mode.

Avoid `any`.

---

## Architecture

Architecture style:

- Modular Monolith
- Lightweight DDD
- Clean Architecture

Business logic belongs to the Domain Layer.

Application orchestrates.

Infrastructure implements contracts.

Presentation consumes Application.

---

## Frontend

Framework:

Next.js

UI:

React

Styling:

Tailwind CSS

State Management:

Prefer local state.

Use shared state only when necessary.

---

## Backend

Backend services are provided by Supabase.

Business logic is organized by domain.

Database access remains encapsulated.

Never expose persistence details to the UI.

---

## Database

Database:

PostgreSQL

Guidelines:

- UUID primary keys
- Soft deletes when appropriate
- Row Level Security
- Explicit constraints
- Database enforces invariants when possible

---

## Offline First

Nova POS is Offline First.

Offline support is mandatory.

Every write operation follows:

```
Local

↓

Queue

↓

Synchronization

↓

Remote
```

Never write directly to the remote database first.

Every feature must consider:

- Local persistence
- Synchronization
- Conflict detection
- Recovery

---

## Authentication

Nova POS

- Local authentication
- Username/password
- Offline login

Nova GanaMás

- Supabase Auth
- Email OTP

Authentication is product-specific.

---

## Domain Rules

Business rules belong only in the Domain Layer.

Application coordinates.

Infrastructure adapts.

Presentation displays.

Never duplicate business rules.

---

## Result Pattern

Business operations return:

```
Result<T>
```

Errors should be explicit.

Avoid exceptions for expected business failures.

---

## API Design

Use REST APIs.

Keep endpoints resource-oriented.

Avoid unnecessary nesting.

Return predictable responses.

---

## Error Handling

Errors must be explicit.

Never swallow exceptions.

Return meaningful messages.

Log unexpected failures.

---

## Security

Validate every input.

Use least privilege.

Encrypt credentials.

Never trust client data.

Always enforce tenant isolation.

---

## Testing

Every feature should include:

- Unit Tests
- Integration Tests
- Property-Based Tests for critical business rules

Critical business logic must always be tested.

Every design should define Correctness Properties.

Correctness Properties should be implemented as Property-Based Tests.

---

## Code Quality

Small functions.

Small files.

Single responsibility.

Readable naming.

Avoid duplicated logic.

Keep modules cohesive.

---

## Performance

Optimize only when necessary.

Measure before optimizing.

Prefer maintainability over micro-optimizations.

---
